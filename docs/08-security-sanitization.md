# 08 - امنیت و پاک‌سازی (Security & Sanitization)

ادیتورهای Rich Text به شدت مستعد حملات تزریق اسکریپت (XSS) هستند. سیستم Sanitization وظیفه پاک‌سازی کدهای مخرب را دارد.

## وظایف اصلی
1. **پاک‌سازی هنگام Paste:** وقتی کاربر متنی را از Word یا سایت دیگری کپی و پیست می‌کند، کدهای HTML کثیف و گاهی مخرب وارد می‌شود. این سیستم باید تگ‌های غیرمجاز و استایل‌های Inline را حذف کند.
2. **پاک‌سازی هنگام مقداردهی (Set Content):** اگر محتوای اولیه‌ای که به ادیتور داده می‌شود حاوی اسکریپت باشد، باید خنثی شود.

## روش‌های پاک‌سازی
برای پاک‌سازی (Sanitize)، ادیتور می‌تواند از رویکردهای زیر استفاده کند:
- **استفاده از DOMParser:** ساخت یک سند مجازی در حافظه مرورگر، تزریق کد HTML کثیف به آن، پیمایش (Traverse) روی نودها و حذف تگ‌های `<script>`, `<object>`, `<iframe>` (مگر اینکه صراحتاً مجاز باشند) و رویدادهای inline مثل `onload`, `onclick`.
- **لیست سفید (Whitelist):** تعریف لیست دقیقی از تگ‌ها (مثل `p, b, i, a, img`) و ویژگی‌های مجاز (مثل `href, src`). هر چیزی خارج از این لیست حذف می‌شود.

## هشدار امنیتی مهم
با وجود Sanitizer سمت کلاینت (داخل ادیتور)، **همیشه** داده‌ها باید سمت سرور (Backend) نیز مجدداً Sanitize شوند. لایه کلاینت فقط برای جلوگیری از اجرای اسکریپت‌ها در مرورگر خود کاربر (Self-XSS) و حفظ تمیزی کد است.
