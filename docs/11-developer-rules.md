# 11 - قوانین توسعه‌دهندگان (Developer Rules)

این قوانین برای تمام مشارکت‌کنندگان (Contributors) و توسعه‌دهندگان پروژه Penman Editor الزامی است.

## 1. قانون استقلال (Zero Dependency)
هیچ وابستگی به کتابخانه‌های ثالث (مانند jQuery, Lodash, React و غیره) در سورس کد مجاز نیست. فقط استفاده از ابزارهای Build (مثل Vite, TypeScript, ESLint) به عنوان `devDependencies` مجاز است.

## 2. سازگاری مرورگرها
کدها باید با مروگرهای مدرن (Chrome, Firefox, Safari, Edge) سازگار باشند. پشتیبانی از IE11 الزامی نیست. در صورت استفاده از APIهای جدید، باید اطمینان حاصل شود که به درستی Fallback دارند یا از Polyfill‌های مناسب در زمان بیلد استفاده می‌شود (بدون تحمیل حجم اضافی به کاربر نهایی).

## 3. اصول کدنویسی
- **زبان:** در صورت استفاده از TypeScript، تایپ‌ها باید تا حد امکان Strict باشند (`any` محدود شود). در صورت استفاده از Vanilla JS، استفاده از JSDoc برای تعریف نوع‌ها توصیه می‌شود.
- **نام‌گذاری:**
  - کلاس‌ها: `PascalCase`
  - متغیرها و توابع: `camelCase`
  - ثابت‌ها: `UPPER_SNAKE_CASE`
- **ماژولار بودن:** هر فایل باید فقط یک کار مشخص انجام دهد (Single Responsibility). توابع طولانی باید به توابع کوچکتر شکسته شوند.

## 4. رویدادها (Events)
تمام ارتباطات مهم بین ماژول‌ها باید از طریق Event Emitter ادیتور انجام شود تا Coupling (وابستگی متقابل) بین کلاس‌ها به حداقل برسد. از فراخوانی مستقیم متدهای یک کلاس از داخل کلاس نامرتبط خودداری کنید.

## 5. مدیریت DOM
عملیات خواندن و نوشتن روی DOM باید تا حد امکان بهینه‌سازی شود. از تغییر مکرر `innerHTML` خودداری کنید و ترجیحاً از متدهای `appendChild`, `insertBefore` و ایجاد Document Fragment استفاده کنید.

## 6. کامیت‌ها و PRها
- پیام کامیت‌ها باید واضح و توصیفی باشند (مانند `feat: add image plugin` یا `fix: resolve selection issue on paste`).
- قبل از ارسال Pull Request، اطمینان حاصل کنید که تمام تست‌ها पास شده‌اند و کد از نظر Linter خطایی ندارد.

## 16. قانون مستندسازی پلاگین‌ها
- **هر پلاگین باید ساختار پوشه‌بندی مستقل و یک فایل راهنمای `.md` مختص به خود داشته باشد.**
- فایل‌های راهنما باید به همراه کد پلاگین در مسیر مربوطه (مثلاً `plugins-docs/PluginName/README.md`) قرار گرفته و هرگونه تغییر یا به‌روزرسانی در عملکرد پلاگین‌ها، باید به طور همزمان در این فایل‌های راهنما نیز منعکس گردد.
-  لیست فایل ها که باید به‌روزرسانی شوند: README.md, examples.md, spec.md, usage.md
